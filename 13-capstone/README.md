# Cloud Engineering Capstone

Status: Planned — implementation has not started.

## Project objective

Combine the portfolio skills into a documented, reproducible application platform with delivery, operations, and recovery.

## Technologies

AWS, Terraform, Docker, GitHub Actions, ECS or EKS, a database, monitoring and backup tools

## Learning goals

- Make and explain architecture decisions based on requirements, cost, and operational effort.
- Integrate infrastructure, application delivery, observability, and recovery.
- Communicate implementation evidence, limitations, and future improvements.

## Prerequisites

- Complete the earlier foundations and the platform track you choose.
- A small application, defined requirements, and an AWS account with scoped permissions.
- An explicit budget, cleanup plan, and disposable demonstration data.

## Implementation checklist

- [ ] Define users, functional requirements, service objectives, budget, and acceptance criteria.
- [ ] Draw the architecture and record the rationale for choosing ECS or EKS.
- [ ] Implement network, identity, compute, and data infrastructure with Terraform.
- [ ] Containerize the application and create a tested CI/CD release process.
- [ ] Configure runtime secrets, health checks, dashboards, alerts, and an operations runbook.
- [ ] Demonstrate deployment, rollback, failure diagnosis, and backup restoration against acceptance criteria.
- [ ] Publish sanitized evidence, architecture decisions, cost observations, and a retrospective; tear down lab resources and verify cleanup.

## Portfolio evidence

As you implement this project, add your architecture diagram, setup and validation instructions, sanitized screenshots or command output, troubleshooting notes, and lessons learned. Record design tradeoffs and cleanup results. Keep credentials, private keys, real customer data, and sensitive state out of the repository.
